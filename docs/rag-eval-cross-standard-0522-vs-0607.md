# RAG 评测口径辨析:05-22 vs 06-07(宋工第三方 + 我们自评 三套标准)

> 起因:宋工第三方评估显示「优秀+良好」从 **88%(05-22)降到 82%(06-07)**,但我们自评打到 **90 分**,出现「我们说变好、他们说变差」的背离。本文拆清这个背离,并给出可比的逐题 delta 与真回归清单。
>
> 数据来源:
> - 结构化、可靠:[../test-docs/eval_merged.json](../test-docs/eval_merged.json)(50 题 question/gt_answer/llm_answer)、[../test-docs/eval_report_all.xlsx](../test-docs/eval_report_all.xlsx)(含「评定依据 / 等级」列)。
> - 外部产物:宋工两份评估报告(`评估报告-宋工-05-22.md` 80 题 / `评估报告-宋工.md` 06-07 50 题),原件不在仓库,逐题评级经报告自带汇总数(优良率、不合格数)交叉校验;个别「优秀↔良好」内部判定可能 ±1,不影响优良率与回归结论。

---

## 0. 结论先行

1. **这个背离是「比较错配」,不是真矛盾。** 你把「我们的尺子评旧一轮 = 90 分」直接对比「宋工的尺子评新一轮 = 82%」——评分标准换了,被评的那一轮跑批也换了。
2. **同标准、同口径**(都用宋工的尺子、都取同样 50 题):06-07 相对 05-22 是 **≈86% → 82%**,落差只有 ~4pp,**完全在评测噪声带(~6.6pp,见 §4)以内**,统计上不构成「变差」。
3. 但拆到逐题,有 **4 道真回归**(Q14/Q28/Q38/Q39)和 **3 道顽固检索失败**(Q6/Q18/Q24)值得单独修——这才是优良率被拖低的真实部分。
4. **「90 分」撑不起「这次变好」的结论**:它来自我们自评(优秀占 72% 的宽松尺),且评的是**更早一轮**的输出(Q1 还答对地质任务);06-07 那一轮我们**根本没用同一把尺子重评**。

| 评级体系 | 优秀 | 良好 | 合格 | 不合格 | 优良率 | **优秀占比** | 加权均值* | 评的哪一轮输出 |

**怎么读这张表:**
- 三者优良率都落在 82–88%,差异全在噪声带内,**没有谁碾压谁**。
- 真正拉开的是**优秀占比**:我们 72% vs 宋工 16–26%。「90 分」是把大量「宋工眼里的良好」打成了优秀堆出来的,是**尺子松**,不是质量高。
- 我们这把尺子**只评过 05-22 轮**(第 1、3 行同轮)。拿它的 90 分去对比宋工评 06-07 轮的 82%(第 2 行),等于「我用旧考卷给自己宽松打 91」对「他用新考卷严格打 80」,不可比。

## 3. 三类清单(按是否值得修排序)

**A. 真回归(内容确实变差,优先修——多为检索召回退化):**
- **Q14** 顺北43 起止日期:召回到错误日期段,整段错。
- **Q28** 永安软泥区:召回变浅,丢具体工艺措施。
- **Q38 / Q39** 张集东:召回不全,丢断层落差阈值、具体煤层编号。

**B. 顽固检索失败(跨轮一直错,非本轮新增,根因是 Retrieval 命错文档):**
- **Q6** 顺北21 技术难点:持续被「风沙/试验报告」干扰,检索不到《工程设计》里的深层成像/断裂/火成岩。
- **Q18** 2014 观测系统:持续给极简错误观测系统。
- **Q24** 顺中二期对策:持续只答 3 点。

**C. 判级 / 一致性存疑(说明「头条数字」本身不够稳):**
- **Q1(06-07)**:知识库答案是「蚂蚁追踪定义」(答非所问),宋工却判**良好**。对比 xlsx 同题 05-22 轮 `llm_answer` 是正常的地质任务回答(优秀)——证明 06-07 那一轮 Q1 **真的答崩了**,但被评级漏过。这种判级松动会让 82% 这个数本身带噪声。

**D. 真改进(尺子之外的真实进步):**
- **Q36** 方山新井资料处理:合格→优秀,关键技术补全。
- **Q23 / Q31 / Q46 / Q49 / Q50**:要点/数据更完整。

## 4. 评测噪声基线:~6.6pp(必须先量噪声再谈信号)

宋工 05-22 那份其实把**同一批 30 题(顺8北/顺中/苏北/煤矿)在同一天跑了两遍**(报告第二份 Q21-50 与第三份 Q51-80 同题同序):

| 跑批 | 优良率 |
|---|---|
| 第一遍 | 86.7% |
| 第二遍 | 93.3% |

**同题同日,纯 RAG 不确定性(温度 / 召回打平 / 重排序)就甩 6.6pp。** 所以 82% vs 86% 的差落在噪声里;**只有超过这个带宽的变化才算信号**。

## 5. 方法论建议(给后续评测固化)

1. **同标准 + 同轮次才能比。** 别再用「我们尺子评旧轮」对「宋工尺子评新轮」。对外引用基线统一到同口径(86%),不要用 80 题的 88%(题量、题难混入)。
2. **报全分布 + 均值 + 优秀占比,不要只报优良率。** 三者一起,才看得出是「顶部变好 + 个别中段掉线」的极化,而非整体下滑。
3. **每轮都跑成结构化产物。** 06-07 这轮目前只有宋工的乱码报告,缺 `eval_merged.json` / `eval_report_all.xlsx` 这套(题目→答案→评定依据→等级)。把每轮都固化成这套结构并存档,形成可比时间序列,「90 分自说自话」才能终结。
4. **逐题 delta 持续跟踪**,优先修 §3.A 真回归与 §3.B 顽固检索失败——这两类是优良率的真实失分点,也是 RAG 真正的瓶颈(Retrieval,而非生成)。
5. **降评测噪声**:固定 temperature=0 或每题多跑取多数,把 6.6pp 的抖动压下来,否则真改进会被噪声淹没。
