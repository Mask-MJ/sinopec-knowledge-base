# 知识库助手初始化

问答入口为 `/qa`，使用当前用户可见、ID 最小的非通用助手。普通用户通过 `/portal` 进入问答；管理员通过 `/assistant` 管理助手，通过 `/knowledgeBase` 管理知识库，使用同一登录入口 `/login`。

应用启动完成账号、角色、菜单和字典初始化后，会在后台检查是否存在全公司共享的非通用助手。这项检查在已初始化的数据库上也会执行。

- 已有共享助手时保持其模型、知识库关联和其他设置，不再创建。
- 缺少共享助手时，取 ID 最小、已关联 RAGFlow 且权限为全公司共享的知识库，由管理员创建「物探知识库助手」。只关联一个知识库，避免混合不同向量模型。
- 私有、部门共享和没有 RAGFlow 关联的知识库不会自动绑定到共享助手；原有知识库的权限不被修改。
- 模型和参数复用正常助手创建流程：优先使用 `ASSISTANT_DEFAULT_MODEL`，否则选择 RAGFlow 上可用的聊天模型，并使用现有默认检索和采样参数。
- 没有符合条件的知识库或管理员时输出配置提示。RAGFlow 暂不可用时输出警告，不阻塞 HTTP 监听和健康检查，下次应用启动重试；不会在数据库中伪造助手记录。
- 适用于当前单机单应用容器部署。初始化检查保证顺序重启不重复创建，不保证多实例同时启动时只创建一个助手。

首次部署须先在 RAGFlow 配置聊天和向量模型，再在应用中创建知识库并选择「全公司共享」。之后重启应用可自动补建助手，或直接由管理员在 `/assistant` 创建助手、关联知识库并选择「全公司共享」。文档需要上传并完成解析才能用于知识问答。

聊天记录按登录账号隔离，同一账号在不同设备共用记录。共享助手的流式与非流式发送均校验会话归属，管理员也不能通过发送接口操作其他账号的会话。API 未指定会话 ID 时，应用先创建并登记属于当前账号的会话，再发送问题；每个新会话保持独立上下文。
